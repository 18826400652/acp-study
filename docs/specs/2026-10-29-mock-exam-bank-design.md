# 官方风格模拟题库 设计

日期：2026-10-29　范围：仅 ACP 题库的模拟考；练习题和面试题库不受影响

## 1. 背景与目标

用户参加了阿里云官网的模拟考试，发现 app 里的模拟考和官网风格差别很大。官网这 20 道样题（15 单选 + 5 多选）全部是场景题：给一个具体业务和问题，问「哪种做法最合理 / 最有效 / 最合适」，不引用课程，选项是具体工程动作。

现有 300 道题的定位是「学完考点后刷知识点」，其中场景式只有约 30 道，76 道带「按课程」字样，适合练习，不适合模拟考。

目标：

1. 新建一套 150 道的官方风格模拟题库，与练习题分开。
2. 模拟考每场从这套题库抽 75 道（50 单选 + 25 多选），连续两场不重复。
3. 模考错题照常进错题本，可以和练习题错题一起复习。
4. 练习题 300 道保持原样。

成功标准：打开模拟考，题目读起来像官网样题；连续两場模考没有重复题；模考错题能在错题本里找到并重刷；现有练习、学习、进度全部不受影响。

## 2. 数据模型

新增 `data/mock/<domain>.json`，每个考点一个文件。字段与现有题目一致：

```json
{
  "id": "rag-m001",
  "domain": "rag",
  "type": "single",
  "stem": "你接手一个 RAG 客服系统……以下哪种做法最合理？",
  "options": ["具体做法 A", "具体做法 B", "具体做法 C", "具体做法 D"],
  "answer": [2],
  "explanation": "正确项为什么对；其余选项错在哪里。",
  "source": "2_5_优化RAG应用提升问答准确度、2_4_自动化评测答疑机器人的表现"
}
```

- id 格式 `<domain>-mNNN`，例如 `rag-m001`。每考点从 `m001` 连续编号。
- `source` 允许用「、」连接多个章节；每个章节必须是已知章节（任一考点的 `chapters`，或 `EXTRA_CHAPTERS`）。练习题也改用同样的来源校验，现有单章节来源不受影响。
- 解析必填，写清正确项为什么对、干扰项错在哪里。
- 不新增字段；题型仍为 `single`（恰好 1 个答案）和 `multi`（2 或 3 个答案）。

### 题量分配

| 考点 | 单选 | 多选 | 合计 |
|---|---|---|---|
| app-dev | 18 | 8 | 26 |
| prompt | 14 | 8 | 22 |
| rag | 20 | 10 | 30 |
| finetune | 16 | 8 | 24 |
| agent-mm | 16 | 8 | 24 |
| production | 16 | 8 | 24 |
| 合计 | 100 | 50 | 150 |

每场模考的配额由现有 `allocate` 按权重算出：单选 9/7/10/8/8/8，多选 4/4/5/4/4/4。题库的两套数量正好等于「一场配额 × 2」，所以任意两场可以互补。

## 3. 组卷与抽题

- 模拟考只从 `mockQuestions` 抽题，不再使用练习题。
- `buildExam(domains, pool, rng, { excludeIds })` 增加排除集合：先排除上一场用过的题，再按考点和题型配额抽取。
- 如果某个考点/题型的剩余题不够配额，回退到包含被排除的题，保证仍能组成 75 题；返回值增加 `reusedCount`，界面在开始前提示「本次有 N 道是上一场做过的题」。
- 由于题库是两整卷，正常情况：第一场抽走一半，第二场从剩余一半抽，两场无交集；第三场排除第二场后回到第一场的一半，如此交替。
- 上一场从 `progress.exams` 的最后一条记录取 `questionIds`。没有历史记录时不排除。

## 4. 数据加载与错题本

`loadData()` 新增：

- `mockQuestions`：全部模拟题。
- `allQuestions`：练习题 + 模拟题。
- `questionById`：由 `allQuestions` 建立，成绩回看和错题本都用它。
- `questions` 保持为练习题，练习、学习统计、考点完成度不受影响。

错题本：

- `wrongQuestions` 改为从 `allQuestions` 过滤，模考错题因此可见。
- 错题练习把模拟题和练习题一起练；按考点筛选照常工作。
- 旧考试记录里的练习题 id 仍能在 `questionById` 找到，历史成绩不受影响。

加载容错：

- 某个 `data/mock/<domain>.json` 缺失或格式错误时，只把该考点的模拟题置空并 `console.error`，不影响其他页面。
- 模拟题库整体为空时，模拟考入口显示「模拟题库还没有生成」，不静默退回练习题。
- `sw.js` 的 `DATA` 预缓存列表加入 `data/mock/<domain>.json`，保证离线也能开始模拟考。

## 5. 校验规则

新增 `validateMockData({ domains, mock }, { strict })`，在 `scripts/validate-lib.mjs` 中导出，由 `scripts/validate-data.mjs` 读取 `data/mock/*.json` 后调用。

规则：

- id 匹配 `^<domain>-m\d{3}$`，同考点内连续且不重复。
- `domain` 与文件一致；`type` 为 `single` 或 `multi`。
- 选项 4 个，不能为空或重复；单选题不出现「以上都对」类选项。
- 单选恰好 1 个答案；多选 2 或 3 个；下标不越界、不重复。
- `stem`、`explanation` 非空；解析至少 20 字，便于核查。
- `source` 用已知章节，允许多章节。
- 严格模式下每考点题量与第 2 节表格完全一致。
- 答案分布：每个考点单选题的正确选项字母占比不超过 40%；多选题中 2 个答案的题占 60%–90%，其余为 3 个答案；任一选项作为正确答案出现在超过 70% 的多选题中则报错。
- 正确答案是严格最长选项的单选题不超过 35%，避免靠长度猜答案。

`npm run validate` 全量检查练习题和模拟题；`--domain <id>` 严格检查该考点的模拟题数量；`--allow-partial` 在内容补齐前跳过数量检查。

## 6. 内容风格与覆盖清单

### 6.1 风格

- 题干公式：「具体角色/业务场景 + 一个明确问题 + 以下哪种做法最合理/最有效/最合适/最稳定？」
- 不出现「按课程」「课程指出」；不引用笔记原文。
- 选项是具体可执行的工程动作，不写空泛概念；干扰项用常见错误做法（换更大模型、调高温度、全量微调、加大上下文窗口、堆更多数据等）。
- 单选 4 个选项、1 个正确；多选 4 个选项、2 或 3 个正确。
- 解析：先说正确项为什么对，再逐条说干扰项错在哪里。
- 中文全角标点；数字、参数名、产品名与笔记一致。
- 内容必须能在课程笔记里找到依据；`source` 写明依据章节，便于逐题核查。官方样题只作为风格参照，不照搬原文。

### 6.2 覆盖清单

官方 20 道样题涉及的主题，每个至少对应一道模拟题：

| 主题 | 对应考点 |
|---|---|
| 分词与词表大小对 Input Token 的影响 | app-dev |
| 逐 Token 采样导致输出差异 | app-dev |
| 少样本示例 / 结构化输出约束 | prompt |
| RAG 权限控制与越权访问 | rag / production |
| 关键词 + 向量混合检索 | rag |
| 检索后重排序 | rag |
| 专业术语库与术语翻译 | prompt / rag |
| 表格内容解析与保结构入库 | rag |
| 相似度阈值过高导致召回不足 | rag |
| 复杂文档（PPT/流程图）解析 | rag |
| 过拟合与验证损失 / checkpoint 选择 | finetune |
| 微调前的数据质量与基座能力评估 | finetune |
| 敏感操作封装为 MCP 工具 + 应用层校验 | agent-mm |
| 数据不出公有云的本地多模态链路 | production |
| 关键词拦截误拦与语义意图识别 | production |

| 部署与成本/稳定性取舍 | production |

## 7. 界面文案

- 模拟考介绍页增加一行：「每次从 150 道模拟题中抽 75 道，并避开上一场做过的题。」
- 开始前如发生回退（`reusedCount > 0`），提示本次有几道是上一场做过的题。
- 其余规则、答题卡、计时、交卷、成绩页不变。

## 8. 测试

单元测试：

- `validateMockData`：数量、id、选项、答案、来源、解析、答案分布各一条通过/失败用例。
- `buildExam` 排除逻辑：150 道 fixture 下，第二场与第一场无交集；第三场可与第一场有交集；题库不足时回退仍返回 75 题并给出 `reusedCount`。
- 数据加载：模拟题缺失时 `mockQuestions` 为空、其他数据正常。

e2e：

- 模拟考从模拟题库出题：开始后第一题属于 `mockQuestions`，不是练习题。
- 连续两场模考无重复题。
- 模考答错后，错题本出现该题，能进入错题练习。
- 练习题入口仍然只有 300 道练习题，学习页统计不变。
- Service Worker 预缓存包含模拟题库，断网后仍能开始模拟考。
- 4 个安卓视口下无横向溢出。

现有测试全部保持通过。

## 9. 执行顺序

1. **代码**：数据加载、`buildExam` 排除逻辑、错题本兼容、校验与测试。先用少量 fixture 跑通；模拟题数量检查暂时用 `--allow-partial`。
2. **12 道样题**：每考点 2 道（1 单选 + 1 多选），写进 `data/mock/*.json`，连同解析一起交给用户确认风格和难度。
3. **用户确认后批量写剩余 138 道**：按考点分批，每个考点一个内容任务；每批由核查子代理对照笔记逐题检查，并检查官方主题覆盖清单。
4. **收尾**：全量校验（严格数量）、`npm test`、4 视口 e2e、更新 README、`npm run bump` 升到 acp-v17。

## 10. 不做的事

- 不改现有 300 道练习题。
- 不做固定 A/B 两套卷，用「排除上一场」实现互补。
- 不新增页面或路由，模拟考沿用现有入口。
- 不把官方 20 道题原文收录进仓库。
- 不把模拟题混进「学习 → 练习」的题目池。

## 11. 风险

- **内容工作量大**：150 道场景题都要写解析并逐题核查。用 12 道样题先对齐风格，再分批生产，降低返工。
- **风格漂移**：写手容易退回「知识点复述」。核查清单把「是否场景化、是否出现按课程、选项是否具体」列为必查项。
- **抽题互补失效**：如果某考点题量写少了，第二场会回退重复。严格数量校验和 `reusedCount` 提示可以发现。
- **错题本混入模拟题**：用户可能只想复习练习题错题。本次不做筛选，先观察；如果需要，再在错题本加「练习题 / 模拟题」筛选。
- **旧进度兼容**：考试记录和错题只存 id，新增模拟题 id 不冲突；`questionById` 包含两套题，旧记录照常显示。
