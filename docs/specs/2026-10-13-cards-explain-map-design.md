# 卡片讲解、知识地图与查漏补缺 设计

日期：2026-10-13　范围：仅 ACP 题库（面试题库的卡片格式独立，不受影响）

## 1. 背景与目标

现状问题（调查结论）：

- **漏点**：覆盖表 234 个小节中 58 个无卡片，约一半是前言 / 总结 / 环境准备，其余是真缺口，RAG 最多（19 个）。「多Agent及多模态应用」考点的多模态内容散在 2_1、2_3、3_1、4_3、4_4、5_2，卡片里几乎没有；5_2「总结与展望」未归入任何考点。
- **看不懂**：每张卡是 5 条 ≤40 字的压缩要点，只适合复习，第一次学读不懂。
- **没有图示**：知识点之间的关系、流程先后无法直观看到。

目标：

1. 按课程笔记补齐缺失知识点（卡片总数约 116 → 约 145）。
2. 每张卡增加可展开的通俗讲解（大白话 / 类比 / 考法 / 易混点）。
3. 关键卡片配竖向流程图；每个考点一张可折叠的知识地图，节点可跳转到卡片。

成功标准：手机上任一卡片点「看讲解」能读懂这个知识点讲什么、考试怎么考；从知识地图能看清考点全貌并一键跳卡；校验脚本保证每张卡都有讲解、每张卡都在地图里。

约束（沿用）：

- 内容只取材于课程笔记（`大模型ACP认证教程/` 下的 ipynb）。类比只帮助理解，不得引入笔记以外的事实。
- 纯原生 ES 模块，DOM 只用 `h()` 构建，不用 innerHTML，不引入第三方库；离线可用。
- 已有卡片 id、`points`、学习进度保持兼容。
- 移动端 360px 宽无横向溢出；gzip 包体积 ≤500KB。

## 2. 数据结构

### 2.1 卡片 `explain` 字段（加在 `data/cards/<domain>.json` 的每张卡上）

```json
{
  "id": "rag-c05",
  "domain": "rag",
  "title": "文本向量化与索引存储",
  "points": ["……"],
  "source": "2_2_扩展答疑机器人的知识范围",
  "explain": {
    "plain": "把每段文字变成一个“坐标”，意思越近坐标越近……",
    "analogy": "图书馆按主题摆书，找书只看附近书架。",
    "exam": "常问相似度用什么算、问题和文档是否用同一个 embedding 模型。",
    "confuse": "向量检索按语义找，不是关键词匹配。",
    "flow": [["文档", "切片", "向量化", "入库"], ["问题", "向量化", "检索", "生成"]]
  }
}
```

| 字段 | 必填 | 上限 | 说明 |
|---|---|---|---|
| `plain` | 是 | 150 字 | 大白话：讲清“是什么、为什么、怎么做” |
| `analogy` | 否 | 60 字 | 生活化类比 |
| `exam` | 是 | 80 字 | 考法提示：常见问法、关键判断点 |
| `confuse` | 否 | 60 字 | 易混点 / 常见错误选项 |
| `flow` | 否 | ≤3 条泳道，每条 2–6 步，每步 ≤10 字 | 流程图，每条泳道是一条有先后的步骤链 |

字数按 `[...s].length` 计数，与现有校验一致。

### 2.2 知识地图 `data/maps/<domain>.json`

```json
{
  "domain": "rag",
  "title": "大模型检索增强",
  "children": [
    { "label": "RAG 工作原理", "children": [
      { "label": "两阶段与建立索引", "card": "rag-c01" },
      { "label": "多轮对话问题改写", "card": "rag-c04" }
    ]}
  ]
}
```

- 节点为 `{label, card?, children?}`，`label` ≤20 字，树深 ≤4 层。
- 带 `card` 的是叶子节点；分支节点只有 `label` 和 `children`。
- 每个考点的每张卡至少在该考点地图中出现一次；不得引用其他考点或不存在的卡片。

## 3. 界面

### 3.1 卡片讲解面板（`js/views/learn.js` + 新模块 `js/views/explain.js`）

- 卡片正面保持不变；`flashcard-source` 下方加按钮「看讲解 ▾」（`aria-expanded`）。
- 展开后依次显示带小标题的段落：大白话 / 类比 / 考法 / 易混（可选字段缺省时不显示），有 `flow` 时最后显示流程图。
- 翻到其他卡片时面板收起（不持久化展开状态）。左右滑动翻卡的手势在面板上照常可用。

### 3.2 流程图（`js/views/flow.js`）

- 每条泳道竖向排列：方框 → 向下箭头 → 方框；多条泳道用 CSS grid 并排，等宽。
- 箭头用 CSS 伪元素实现，不用 SVG 库。窄屏上 3 条泳道仍不横向溢出（方框文字可换行）。
- 容器带 `role="img"` 和 `aria-label`（按泳道朗读，如“文档→切片→向量化→入库；问题→……”）。

### 3.3 知识地图页（`js/views/map.js`，路由 `#/map/<domain>`）

- 入口：考点列表每行、卡片页各一个「知识地图」按钮。
- 用原生 `<details>/<summary>` 渲染可折叠树，前两层默认展开。
- 卡片节点渲染为按钮，按学习状态显示「已掌握」/「再看看」标记（复用现有 chip 样式）。点击后先 `setCardPos(domain, cardId)`，再跳转 `#/learn/<domain>`。
- 顶部显示“已掌握 X / 共 Y 张”。考点不存在或没有地图数据时显示 `emptyState`。
- 路由、标题、Tab 高亮（归属「学习」）在 `router.js` / `main.js` 中注册。

### 3.4 数据加载与缓存

- `loadData()` 额外加载 `data/maps/<domain>.json`，结果放在 `data.maps`（按 domain 索引）。
- `sw.js` 的 DATA 列表加入地图文件；完成后 `npm run bump` 升级缓存版本（acp-v16）。

## 4. 内容范围

| 考点 | 补卡（估计） | 讲解 | 流程图 | 地图 |
|---|---|---|---|---|
| RAG | +8：context recall / precision 计算过程、其他推荐指标、问题分类及改进策略、检索前 / 检索后策略、Embedding 模型选择、建立索引 / 检索生成细节、GraphRAG 与模块化 RAG 等 | 全部 | 约 6 张 | ✓ |
| 应用开发 | +3：大模型如何工作（Token、自回归生成等）、2_1 的 RAG 技术方案等 | 全部 | 约 4 张 | ✓ |
| 提示词 | +1 左右 | 全部 | 约 3 张 | ✓ |
| 微调 | +3：训练数据格式、训练结果观察、合并 LoRA 参数 | 全部 | 约 4 张 | ✓ |
| 多Agent及多模态 | +2（3_7 用 Skill 固化专家经验等）+ 5–6 张多模态卡（汇总 2_1/2_3/3_1/4_3/4_4/5_2） | 全部 | 约 6 张 | ✓ |
| 生产实践 | +3：降低资源消耗、安全风险总览、间接提示词注入 | 全部 | 约 4 张 | ✓ |

- 补卡数量是估计值。以执行时逐节对照笔记的结果为准，不为凑数补卡，前言 / 总结 / 纯环境操作不补。
- 5_2 的非多模态要点按主题归入对应考点。确有考点价值才补卡，同时更新覆盖表。
- 新卡 id 接续现有编号，放在文件中对应章节的位置。`docs/coverage/*.md` 的卡片列同步更新，多模态卡加一组「多模态（跨章节）」行。
- 流程图只用于有明确先后顺序的知识（如 RAG 两阶段、Agent 工具调用循环、蒸馏流程、评测先行流程），不硬套。
- `domains.json` 不改。多模态卡的出处用 `source` 字段写明来源章节；跨章节时用「、」连接，如 `2_1_…、4_3_…`。

## 5. 校验与测试

`scripts/validate-lib.mjs`：

- `CARD_RANGE.max` 25 → 35。
- 每张卡必须有 `explain`，`plain`、`exam` 非空。各字段不超过 2.1 节的字数上限，`flow` 的形状合法。不允许出现未知字段。
- 地图：文件存在，`domain` 匹配，节点形状合法，`label` 不超过字数上限，树深 ≤4。`card` 必须属于本考点，本考点每张卡至少出现一次。

测试：

- 单元测试（node:test）：上述每条校验规则的通过 / 失败用例；地图数据工具函数（如统计已掌握数、收集卡片 id）。
- e2e（Playwright，4 个安卓视口）：
  - 展开 / 收起讲解，翻卡后自动收起；
  - 流程图与讲解面板无横向溢出；
  - 地图页折叠展开；
  - 点节点后跳到对应卡片，刷新后位置仍在；
  - 已掌握标记显示正确。
- 现有测试全部保持通过。包体积检查仍需 ≤500KB。

## 6. 执行顺序

1. **代码**：数据结构、讲解面板、流程图、地图页、校验与测试，用少量示例数据跑通。为不让校验在内容补齐前失败，`explain` 必填和“每卡入图”两条规则在第 2 步全部完成后再打开。由计划给出具体开关方式，最终必须是强制的。
2. **内容**：按考点逐个执行（多Agent 考点拆成“原有内容”和“多模态”两个任务）。每个任务依次是补卡、写全部讲解、做流程图、做地图、更新覆盖表。每个任务都由核查子代理对照笔记逐条查证。
3. **收尾**：打开强制校验，更新 README 卡片数，整体审查。在本地合并，用户明确要求后再推送，然后升级到 acp-v16。

## 7. 不做的事

- 不改面试题库的卡片和页面。
- 不引入 markmap 等导图库，不做放射状大导图。
- 不改练习题、考试的逻辑与题库内容。
- 不持久化讲解面板的展开状态。
