- 目标用户：准备 Agent 开发岗位面试的本人，在安卓手机上碎片化复习

## 1. 背景与目标

面试题库位于本机的面试准备目录（下称「prep 目录」，构建时由 `INTERVIEW_SRC` 指定）的 `qbank/` 下，共 8 类 115 道开放问答（A 到 H）。每题四段：**结论**、**原理**、**我在项目里怎么做**、**取舍与局限**。内容含个人经历和目标单位信息，本文及仓库内任何文件都不引用其原文。prep 目录属于一个没有远程的本地 git 仓库。

**目标：** 在现有 acp-study App 中加入第二个题库「Agent 面试」，提供翻卡自评、约 120 道选择题、计时模拟面试。**面试内容只以密文形式进入公开仓库和线上站点**，在手机上输入密码后在本机解密。

**非目标：** 多用户、服务端鉴权、在线修改题库、对 ACP 题库做任何行为改动。

| 类别 id | 文件 | 名称 | 题数 | 模拟面试权重 | 选择题 |
|---|---|---|---|---|---|
| `iv-a` | A-agent-core.md | Agent 核心范式 | 25 | 20 | 约 30 |
| `iv-b` | B-rag.md | RAG | 20 | 18 | 约 25 |
| `iv-c` | C-protocols.md | 协议（MCP 等） | 10 | 8 | 约 15 |
| `iv-d` | D-engineering.md | 工程化 | 15 | 12 | 约 20 |
| `iv-e` | E-evaluation.md | 测评 | 10 | 10 | 约 15 |
| `iv-f` | F-medical.md | 医疗信息化 | 10 | 8 | 约 15 |
| `iv-g` | G-project.md | 项目深挖 | 20 | 18 | 无 |
| `iv-h` | H-behavioral.md | 行为与动机 | 5 | 6 | 无 |

类别名称以 md 一级标题为准（去掉「（N 题）」后缀）；上表为预期值。

## 2. 安全模型

- **威胁：** 公开仓库里的密文可被任何人下载后离线暴力猜解。唯一防线是密码强度。
- **密码要求：** 构建脚本拒绝短于 12 个字符的密码。
- **算法：** Web Crypto。PBKDF2-SHA256 迭代 600000 次，派生 256 位 AES-GCM 密钥；每次构建使用新的随机 12 字节 IV。
- **salt：** 16 字节随机数，首次构建时生成。之后的构建复用已有 `data/interview.enc` 中的 salt，这样只要密码不变，手机上保存的密钥在内容更新后仍然有效。构建参数 `--new-salt` 可强制换新（改密码时使用）。
- **密文格式** `data/interview.enc`（JSON 文本）：`{"v":1,"kdf":"PBKDF2-SHA256","iter":600000,"salt":"<b64>","iv":"<b64>","ct":"<b64>"}`。明文先 gzip 再加密，`ct` 含 GCM 认证标签。
- **明文不落仓库：**
  - 源文件只在 `prep/` 下；构建过程不写明文中间文件，全部在内存中完成。
  - **防泄漏检查：**
    - 检测词取自本地明文源，包括全部 115 个问答标题、每题「结论」的前 20 个字符，以及 `qbank-app/leak-terms.txt` 中列出的额外敏感词（可选，每行一个，由用户自己维护）。这样检测词本身不会出现在公开仓库里。
    - 检查范围是 `git ls-files` 列出的文件和工作区中未被忽略的文件，任何一个包含检测词就失败。
    - 两处会运行这项检查：一是 `build:interview` 在写出密文之前自动运行；二是单元测试 `tests/unit/no-plaintext.test.mjs`，在设置了 `INTERVIEW_SRC` 时运行，未设置时跳过并输出提示。
  - 测试夹具只使用虚构内容。
- **已知限制（写进 README）：** 改密码不会使旧密文失效，旧密文永久留在 git 历史中，可以用旧密码解开。
- **本机密钥：** 解密成功后，把派生出的 CryptoKey（`extractable: false`）存入 IndexedDB（库名 `acp-keys`，键为 `interview`）。设置页「锁定面试题库」删除该密钥，并清空内存中的明文。能拿到已解锁手机的人可以看到内容，这一点可以接受。

## 3. 构建与数据

### 3.1 明文源

| 路径（相对 `prep/`） | 维护者 | 内容 |
|---|---|---|
| `qbank/*.md` | 用户本人 | 115 道问答，格式由 `check_prep.py` 约束 |
| `qbank-app/questions/iv-*.json` | 出题批次 | 选择题，格式与 ACP 题目相同（ACP 设计 §4）；`source` 为问答编号，如 `"A3"` |

### 3.2 md 解析（`scripts/interview-lib.mjs`）

- **题目识别：** 用正则 `^### ([A-H])(\d+)\. (.+)$` 识别题目，编号必须从 1 连续递增。
- **四段切分：** 用段首的粗体标签切分（`**结论**`、`**原理**`、`**我在项目里怎么做**`、`**取舍与局限**`）。标签后可带「 ⚠️」和中英文冒号；缺少任一段即报错，并指出文件名和题号。
- **块级格式：** 每段正文解析为块数组，支持三种块：段落 `{t:"p"}`、无序列表 `{t:"ul"}`、有序列表 `{t:"ol"}`。
- **行内格式：** 只支持三种，渲染为片段数组 `[{t:"text"|"b"|"code", s:"..."}]`：
  - `**粗体**`
  - `` `代码` ``
  - 纯文本
- **未知语法：** 遇到其他 md 语法时按纯文本保留，不报错。
- **安全：** App 端全部用 `textContent` 构建 DOM，不使用 `innerHTML`。
- **标记：**
  - 【待补…】和【待 Task 12…】片段标为 `{t:"todo"}`；
  - 卡片上有这类片段时，加 `hasTodo: true`。
- 文件开头的引言块（`>` 行）作为类别说明，显示在类别页顶部。

### 3.3 生成的明文结构（只存在于内存）

```json
{
  "version": 1,
  "builtAt": "2026-10-01T12:00:00Z",
  "domains": [{"id":"iv-a","letter":"A","name":"Agent 核心范式","intro":[...],"weight":20,"target":{"single":0,"multi":0}}],
  "cards": {"iv-a": [{"id":"iv-a-c01","domain":"iv-a","no":"A1","title":"什么是 Agent？…","parts":{"conclusion":[...],"principle":[...],"practice":[...],"tradeoff":[...]},"hasTodo":false}]},
  "questions": {"iv-a": [ … 与 ACP 题目同结构 … ]}
}
```

- **id 规则：**
  - 卡片 id 为 `<类别>-c<两位序号>`，序号即题号，例如 A1 → `iv-a-c01`。这样 md 里的题号不变，卡片 id 就不变，自评进度也不会丢。
  - 选择题 id 为 `<类别>-<三位序号>`。
- **target：** 取值为选择题的实际题数（单选 / 多选各自计数）。严格模式下的题量校验以本文 §1 表格为准，允许偏差 ±3。

### 3.4 构建命令

- `npm run build:interview`
  - 输入：环境变量 `INTERVIEW_SRC`（prep 目录）和 `INTERVIEW_PASSWORD`。
  - 流程：解析 md → 校验选择题 → 打包 → gzip → 加密 → 写 `data/interview.enc` → 打印卡片数、题数和密文大小。
  - 结果：任一步出错就退出，不写文件。
- `npm run decrypt:interview -- <输出目录>`：用密码把 `data/interview.enc` 解回明文 JSON。这是恢复手段，输出目录必须在仓库外，脚本会拒绝仓库内的路径。
- **题目校验：** 复用 `validate-lib.mjs`，扩展出按题库配置的参数：类别列表、合法 `source` 集合（问答编号）、各类别目标题数。ACP 的校验行为不变。

## 4. App 改动

### 4.1 题库切换与路由

- **切换控件：** 首页顶部加两段式切换「ACP 认证 | Agent 面试」。当前题库存在 localStorage 键 `acp-bank`（值为 `acp` 或 `interview`），打开 App 时进入上次的题库。
- **路由：**
  - 面试题库的路由统一加前缀 `#/iv`：`#/iv`（首页）、`#/iv/learn/:domain`、`#/iv/practice/:domain`、`#/iv/mock`、`#/iv/mock/result`、`#/iv/wrong`、`#/iv/unlock`。
  - ACP 的全部路由不变。
  - 底部 Tab 的链接按当前题库切换，设置页共用。
- **锁定时的跳转：** 未解锁时访问任何 `#/iv/*` 路由，一律渲染解锁页；解锁成功后回到原路由。

### 4.2 解锁页

- 页面有一个密码输入框和一个「解锁」按钮；解密过程中按钮显示「解锁中…」并禁用。
- **失败提示：**
  - 解密失败（GCM 校验不通过）时，统一提示「密码不对」。
  - 浏览器不支持 `crypto.subtle` 或 `DecompressionStream` 时，提示「当前浏览器不支持，请用 Chrome 或系统浏览器打开」。
- **自动解锁：** 打开 App 时，如果 IndexedDB 里有密钥，就自动尝试解密；失败（例如密码已更换）则删除该密钥，并回到解锁页。

### 4.3 面试进度

- 使用独立的 localStorage 键 `acp-interview-progress-v1`，结构沿用 ACP 进度（`answers`、`wrong`、`exams` 等），另外加三项：
  - `cards`：`{cardId: {grade: "known"|"fuzzy"|"unknown", t}}`，只保留最近一次自评。
  - `mocks`：最近 20 次模拟面试的结果。
  - `mockDraft`：未完成的模拟面试。
- ACP 的进度键和结构不做任何改动。
- **导出 / 导入：**
  - 按当前题库分别进行；面试进度的文件名为 `interview-progress-YYYYMMDD.json`。
  - 导入时校验文件属于哪个题库，不匹配就拒绝。
  - 进度文件只含 id 和时间戳，不含题目原文。

### 4.4 页面

1. **首页 `#/iv`**
   - 8 个类别，每行显示：卡片「会」的数量 / 总数、选择题正确率。
   - 「今日推荐」的优先级：不会的卡片 > 选择题错题 > 模糊的卡片 > 还没看过的类别。
   - 显示最近一次模拟面试的结果。
2. **学习 `#/iv/learn/:domain`**
   - 顶部显示类别说明。
   - **翻卡：**
     - 正面是题号和题目，下方有「看答案」按钮。
     - 背面依次展开四段；「结论」默认展开，其余三段默认折叠，点标题展开。
     - 底部三个自评按钮：会 / 模糊 / 不会。点击后记录并进入下一张。
     - 保留现有卡片的左右滑动和上一张 / 下一张按钮。
     - 带【待补】的片段用醒目的警示色加底纹显示，颜色来自 CSS 变量，深色和浅色模式都要清晰可辨。
   - **筛选：** 「全部」和「只看模糊 + 不会」两个选项。
   - **练习：** 本类有选择题时显示「开始练习」，复用 ACP 的练习页和判分逻辑；G、H 类不显示。
3. **模拟面试 `#/iv/mock`**
   - **开始页：** 说明规则，然后点「开始」。
   - **抽题：** 按 §1 的权重，用最大余数法从 115 张卡片中抽 12 张。余数相同时，权重高的优先；权重也相同时，按类别顺序。每类内部随机抽取，不重复。
   - **每题流程：**
     1. 只显示题目，同时开始 2 分钟软倒计时，超时后数字变红，但不强制翻面。
     2. 点「看答案」后显示四段内容，同时记录用时。
     3. 自评：会 / 模糊 / 不会。
     4. 自评结果同时写回卡片状态，然后进入下一题。
   - **草稿：** 每题自评后都保存草稿。中途离开时不需要确认，回来后从未完成的题继续。
   - **结果页：** 显示会 / 模糊 / 不会各几题、总用时、每题用时。模糊和不会的题附有链接，可以直接打开对应卡片。
4. **错题 `#/iv/wrong`**：只收录选择题，规则同 ACP：连续答对 2 次移出。
5. **设置：** 增加「锁定面试题库」按钮，只在当前是面试题库时显示。

### 4.5 离线与更新

- `sw.js` 把 `data/interview.enc` 加入 data 缓存列表，使用 stale-while-revalidate 策略。
- 每次发布都递增 `CACHE_VERSION`。
- 离线时，只要此前已缓存密文、IndexedDB 里也有密钥，面试题库就能正常使用。

### 4.6 代码组织

- 新增模块：
  - `js/crypto.js`：派生密钥、解密、解压，以及 IndexedDB 中密钥的存取。
  - `js/interview.js`：纯逻辑，包括抽题、卡片自评的状态变换、推荐。
  - `js/views/iv-*.js`：面试题库的各个页面。
  - `js/rich.js`：把块数组和片段数组渲染成 DOM。
- 不需要改动的现有模块直接复用：`scoring.js`、`ui.js`、`storage.js`、`exam.js` 中的 `allocate`，以及练习页。
- 需要改动的现有模块：`router.js`（加 `#/iv` 前缀）、`main.js`（题库上下文）、`views/practice.js` 和 `views/wrong.js`（改为接收题库上下文）。
- 文件大小仍然遵守 ACP 设计的要求：每个文件不超过 400 行，纯逻辑和 DOM 渲染分开写。

## 5. 体积

- 明文 md 共约 147KB。选择题约 120 道，大约 150KB。两者合计 gzip 后，估计密文在 base64 编码前为 80 到 100KB。
- 目前全站 gzip 后是 181KB，加上这部分后仍低于 500KB 的预算。`check-size.mjs` 会把 `interview.enc` 算进去。

## 6. 测试

1. **单元测试**（`node:test`，纯逻辑模块覆盖率不低于 80%）：
   - md 解析：四段切分、⚠️ 标签、编号不连续报错、缺段报错、行内格式、【待补】标记。
   - 加密：加解密往返；密码错误时失败；复用已有 salt；拒绝过短的密码。
   - 抽题：分配结果正好 12 张，且符合权重。
   - 卡片自评状态更新：不修改原对象。
   - 推荐顺序。
   - 进度导入：校验所属题库。
   - 防泄漏测试（见 §2）。
   - 现有 91 个测试全部通过。
2. **端到端测试**（Playwright，沿用 4 个安卓视口配置）：
   - 夹具：用虚构的 2 个类别、6 张卡片、4 道选择题，在测试开始前用测试密码现场生成密文，由测试服务器提供，不提交到仓库。
   - 流程：切换题库 → 输错密码后看到提示 → 解锁 → 翻卡并自评 → 筛选 → 选择题练习 → 模拟面试（草稿保存后恢复）→ 结果页 → 锁定后回到解锁页 → 切回 ACP，ACP 的进度没有变化。
   - 每一步都断言没有横向溢出。
3. **构建检查**：用真实题库运行 `build:interview`，确认输出 115 张卡片；再用 `decrypt:interview` 解回来，与源数据逐项比对一致。
4. **真机验收**：由用户在安卓手机上完成解锁、翻卡、一轮模拟面试，然后断网再打开一次。

## 7. 交付节奏

1. **第一阶段：**
   - 完成加密、构建脚本、题库切换和全部页面。
   - 用真实的 115 张卡片生成密文，选择题暂为空，这时学习页不显示练习入口。
   - 发布后由用户在手机上验收。
2. **第二阶段：**
   - 选择题分 3 批出：A+B、C+D、E+F，每批都要通过校验，出题依据是对应问答的内容。
   - 每批完成后，重新构建并发布。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 密码弱，被离线破解 | 至少 12 个字符；README 说明风险 |
| 忘记密码 | 明文源在本地 prep 目录及其 git 历史里，重新构建即可；README 提醒这台电脑之外没有明文备份 |
| 明文误提交到公开仓库 | 构建不写明文文件；防泄漏测试 |
| 微信 X5 内核不支持 `DecompressionStream` | 解锁页提示改用系统浏览器；ACP 题库不受影响 |
| md 格式变化导致解析失败 | 构建报错时指出文件名和题号；与 `check_prep.py` 使用同一套结构约束 |
| 选择题依据的是本人整理的答案，可能有错 | 出题时只依据问答原文；F 类中标了 ⚠️ 的内容不出题，等核对后再补 |
