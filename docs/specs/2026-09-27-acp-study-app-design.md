# ACP 备考站 设计文档

- 日期：2026-09-27
- 状态：待评审
- 目标用户：备考阿里云「大模型高级工程师 ACP 认证」的本人，主要在安卓手机上碎片化学习

## 1. 背景与目标

考试规则（来自官方大纲）：满分 100，120 分钟，80 分及格，闭卷；单选 50 题 × 1 分，多选 25 题 × 2 分。

| 考点 id | 名称 | 权重 | 主要来源章节 |
|---|---|---|---|
| `app-dev` | 大模型应用开发 | 17% | 2_1、2_2、3_0、3_1 |
| `prompt` | 大模型提示词工程 | 15% | 2_3 |
| `rag` | 大模型检索增强 | 20% | 2_2、2_4、2_5 |
| `finetune` | 大模型微调 | 16% | 4_1、4_2 |
| `agent-mm` | 多 Agent 及多模态应用 | 16% | 3_2 – 3_8（多模态见 §9 风险） |
| `production` | 生产环境应用实践 | 16% | 4_0、4_3、4_4、5_1 |

**目标：** 一个可装到安卓主屏、离线可用的静态学习站，提供「速记卡片 + 分考点练习 + 整套模拟考 + 错题本」。

**非目标：** 账号系统、多端云同步、服务器端、AI 实时问答、iOS 专项适配（iOS 能用即可，不专门调优）。

## 2. 技术方案

纯静态 PWA，无构建步骤：原生 HTML + CSS + JS（ES2019 语法，ES Module），数据为 JSON，Service Worker 离线缓存，GitHub Pages 托管。运行时零第三方依赖。

仓库：`acp-study-app/` 为独立 git 仓库（已加入外层官方课程仓库的 `.gitignore`），推送到用户自己 GitHub 账号下的新仓库。

## 3. 页面与流程

单页应用，`#` 哈希路由；底部固定 4 个 Tab。

1. **首页 `#/`**：考试倒计时（日期可设）、整体正确率；6 个考点进度条（权重 / 已做题数 / 正确率，< 80% 标红）；「今日推荐」按钮，优先级为：待复习错题 > 正确率最低的考点 > 未学考点。
2. **学习 `#/learn/:domain`**：先卡片、后练习。
   - 卡片：左右滑动（也提供上一张 / 下一张按钮），可标记「已掌握 / 再看看」，底部显示来源章节。
   - 练习：每题提交后立即显示对错与解析；未作答的题优先出，其次是答错过的题。
3. **模拟考 `#/exam`**：50 单选 + 25 多选，120 分钟倒计时，交卷前不显示对错。
   - 交卷后显示总分、是否及格、各考点得分，并可逐题回看解析。
   - 进行中每次作答自动保存草稿；退出后可继续，倒计时按开考时间计算（到时自动交卷）。
4. **错题本 `#/wrong`**：自动收录答错的题，可按考点筛选，提供「只刷错题」模式；错题复习时**连续答对 2 次**即移出。
5. **设置 `#/settings`**（从首页右上角进入）：考试日期、导出 / 导入进度、清空进度（需二次确认）。

**判分规则：** 单选答对得 1 分；多选必须与正确答案完全一致才得 2 分，否则 0 分。

**模拟考抽题：** 单选 50 题、多选 25 题，分别按考点权重分配题量，用最大余数法取整（余数相同时权重高的优先，权重也相同时按表格顺序），保证总数正好为 50 和 25。按此规则，单选各考点为 app-dev 9、prompt 7、rag 10、finetune 8、agent-mm 8、production 8；多选为 4、4、5、4、4、4。在每个考点的题池里随机抽题，同一套试卷内不重复；选项顺序不打乱，因为有些选项写的是「以上都对」这类依赖顺序的表述。

## 4. 数据格式

```
data/
  domains.json            # [{id, name, weight, chapters: [...]}]
  cards/<domain>.json     # [{id, domain, title, points: [3-5 条], source}]
  questions/<domain>.json # [{id, domain, type, stem, options, answer, explanation, source}]
```

- `type`：`"single"` 或 `"multi"`；`answer` 是正确选项下标组成的数组，从 0 开始。单选题长度为 1，多选题长度 ≥ 2。
- `id` 格式为 `<domain>-<三位序号>`，卡片为 `<domain>-c<序号>`。**id 一旦发布就不再修改**，因为进度记录靠 id 关联。
- `source` 必须是真实存在的课程笔记文件名（不带扩展名）。

**题库规模：** 约 300 题，按权重分配，单选与多选约 2:1。

| 考点 | 总题数 | 单选 | 多选 |
|---|---|---|---|
| app-dev | 51 | 34 | 17 |
| prompt | 45 | 30 | 15 |
| rag | 60 | 40 | 20 |
| finetune | 48 | 32 | 16 |
| agent-mm | 48 | 32 | 16 |
| production | 48 | 32 | 16 |

卡片每个考点 10–15 张，共约 75 张。

## 5. 进度存储

- 全部存在 `localStorage` 里，只用一个键 `acp-progress-v1`，值为一个 JSON 对象，含 `schemaVersion` 字段，方便以后迁移格式。
- 结构：
  - `answers`：`{questionId: [{t, correct}]}`，每题只保留最近 10 条作答记录；
  - `wrong`：`{questionId: streak}`，streak 为连续答对次数，达到 2 时删除该题；
  - `cards`：`{cardId: "known" | "review"}`；
  - `exams`：历次模拟考结果，只保留最近 20 次；
  - `examDraft`：未交卷的模拟考草稿；
  - `examDate`：考试日期。
- 状态更新一律生成新对象再整体写回，不就地修改。所有读写都包在 try/catch 里；写入失败时页面照常使用，顶部提示「本次进度不会保存」。
- 启动时如果浏览器支持，调用 `navigator.storage.persist()` 申请持久化存储，降低被系统清理的概率。
- **导出**：下载 `acp-progress-YYYYMMDD.json` 文件。**导入**：先校验 `schemaVersion` 和数据结构，不合法时拒绝并说明原因；导入前需确认，导入会覆盖当前进度。

## 6. 离线与更新

- `sw.js` 维护一个带版本号的缓存 `acp-v<N>`。页面框架（HTML/CSS/JS/图标）采用缓存优先；`data/*.json` 采用先返回缓存、后台再拉新版本（stale-while-revalidate）。
- 发布新版本时递增缓存版本号，新 SW 激活时删除旧缓存。
- 检测到新版本后显示提示条「内容已更新，点击刷新」，用户点击后才刷新。模拟考进行中不显示这个提示。

## 7. 安卓适配要求

- 以 360px 宽为基准设计，最窄支持 320px；宽屏下内容最大宽度 560px 并居中。任何宽度都不允许出现横向滚动。
- 布局高度使用 `100dvh`，不支持的浏览器回退到 `100vh`；底部 Tab 加 `padding-bottom: env(safe-area-inset-bottom)`；viewport 设置 `viewport-fit=cover`。
- 可点击区域 ≥ 48×48px，选项整行可点；页面不依赖 hover 效果。
- 卡片区域设置 `overscroll-behavior: contain` 和 `touch-action: pan-y`，由 JS 处理横向滑动，避免误触发下拉刷新或边缘返回手势。
- 路由状态全部放在 URL hash 里，保证安卓返回键或返回手势回到上一页。模拟考进行中拦截返回并弹窗确认。
- 字体使用系统字体栈：`system-ui, "Noto Sans CJK SC", "PingFang SC", "Microsoft YaHei", sans-serif`，不加载网络字体。
- 通过 `prefers-color-scheme` 跟随系统深色 / 浅色模式；颜色统一定义为 CSS 变量；设置 `theme-color` meta。
- `manifest.json` 设置 `display: standalone`，提供 192 和 512 两种尺寸的图标，并包含 maskable 图标。
- 在微信内置浏览器中（UA 含 `MicroMessenger`）显示提示条「点右上角 ··· 在浏览器打开，可添加到主屏」。
- 兼容目标：Chrome / Edge 80+、华为、小米、OPPO、vivo 系统浏览器、微信 X5/XWeb 内核。不使用 `:has()`、容器查询、顶层 `await` 等较新特性。
- 体积预算：整站小于 500KB；未压缩的 JS 加 CSS 小于 150KB（中文界面文案在 UTF-8 下每字 3 字节；GitHub Pages 自动 gzip 后约 35KB）。

## 8. 测试与质量

开发阶段的工具放在 `devDependencies`，不会发布到站点。

1. **单元测试**（`node:test`）：判分、按权重抽题（最大余数法，总数必须正好为 50 和 25）、错题本移出规则、进度导入校验、schema 迁移。纯逻辑模块覆盖率 ≥ 80%。
2. **题库校验脚本** `scripts/validate-data.mjs`：检查 id 唯一且格式正确；`answer` 下标没有越界，也没有重复；单选题恰好 1 个答案、多选题至少 2 个；选项数量在 3–6 之间；`source` 是存在的章节名；各考点题数与 §4 表格的偏差不超过 ±3；单选题中不出现「以上都对」这类措辞。**脚本不通过就不发布。**
3. **端到端测试**（Playwright，模拟 Pixel 5 和 Galaxy S9+，360 和 412 两种宽度，浅色和深色两种模式）：走完「首页 → 学习卡片滑动 → 练习答题 → 模拟考答题并交卷 → 错题本」主流程；断言页面没有横向溢出、底部 Tab 可见且可点；保存截图。
4. **内容自查**：每出完一个考点，逐题检查答案有没有歧义、是否超出笔记范围、干扰项是否合理、解析是否说清了依据。
5. **真机验收**：用户在自己的安卓手机上打开线上地址，完成一轮主流程，并试一下添加到主屏和离线打开。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 题目是根据课程自拟的，不是官方真题，可能和真实考试有出入 | 每道题标注来源章节；首页说明「非官方题库」 |
| **多模态内容在课程中较少**（只在 2_3、4_3、4_4 中零星出现） | agent-mm 考点以多 Agent 为主；多模态题目只依据课程里已有的内容出，数量宁少勿编，缺口在首页注明 |
| 课程之外的阿里云产品细节（百炼、PAI 等）可能会考到 | 首版不扩展；如果之后需要，作为独立的一批题补充，并标注来源为官方文档链接 |
| GitHub Pages 在国内访问不稳定 | 首次打开成功后可离线使用；站点是纯静态文件，可以原样迁移到 Gitee Pages 或阿里云 OSS |
| 浏览器数据被清理导致进度丢失 | 申请持久化存储，提供导出 / 导入功能，设置页提醒定期备份 |

## 10. 交付节奏

1. 应用框架、全部页面功能，加每个考点 5 道样题：先跑通主流程，完成真机验收。
2. 分批出题和卡片，每批 1–2 个考点，每批都要通过校验脚本；推荐顺序为 rag → app-dev → prompt → finetune → agent-mm → production。
3. 每批完成后发布一次，用户在手机上试刷并反馈。

## 11. 目录结构

```
acp-study-app/
  index.html  manifest.json  sw.js
  css/app.css
  js/  main.js  router.js  store.js  scoring.js  exam.js  views/*.js
  data/  domains.json  cards/*.json  questions/*.json
  icons/
  scripts/validate-data.mjs
  tests/unit/*.test.mjs  tests/e2e/*.spec.mjs
  docs/specs/
```

以上文件应在 200–400 行内，都不超过 800 行。纯逻辑（`scoring`、`exam`、`store` 的状态变换）和 DOM 渲染（`views/`）分开写，以便单元测试。
