# V4 大纲模拟题扩充实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 以《阿里云大模型ACP考试大纲-V4.pdf》为范围依据，参考官网模拟题风格，分四批新增 300 道模拟题，使手机备考应用的模拟题库从 150 道扩充到 450 道。

**Architecture:** 沿用现有六个考点的 JSON 模拟题库、按权重组卷、成绩回看和错题本。每批新增 75 道（50 单选、25 多选），完成内容核查及应用校验后再进入下一批；首批先提交 12 道样题确认风格和难度。扩充题量时同步更新严格校验目标和必要的文档、缓存，不另建考试系统。

**Tech Stack:** 原生 JavaScript ES 模块、JSON、Node.js 内置测试、Playwright、Service Worker。

**Spec:** 本文“已确认的任务范围”记录本次对话已确认的安排；内容依据为仓库根目录的 `阿里云大模型ACP考试大纲-V4.pdf`，既有接入设计参考 `docs/specs/2026-10-29-mock-exam-bank-design.md`。旧设计中的 150 道题量是本次扩充前的基线，本次分阶段题量以本文为准。

**日期：** 2026-11-02。

**当前状态：** 用户已确认样题，第一批 75 道全部编写、核查并接入，模拟题累计 225 道；严格校验、单元测试和四种手机视口端到端测试通过。第二至四批尚未实施。详见 [覆盖表](../../coverage/mock-v4.md)、[样题](../samples/2026-11-02-v4-mock-samples.md)和[第一批索引](../../coverage/mock-v4-batch1.md)。

## 已确认的任务范围

- 用途：备考阿里云大模型 ACP 认证，在现有手机应用中随时练习和模拟考试。
- 以用户提供的 V4 大纲确定出题范围；教程提供知识和实操依据，官网截图提供题风参考。
- 新增 300 道题，分四批，每批 75 道；最终模拟题共 450 道。
- 第一批先出 12 道样题，每个考点 1 道单选、1 道多选，等待用户确认风格和难度，再完成该批剩余 63 道。
- 12 道样题计入第一批及新增 300 道总量，不另加题量。
- 样题确认后，后续批次沿用确定的标准推进，无需每批重新确认；影响任务范围的实质变更需说明。
- 各批均混合基础、中等和综合判断题，后续批次侧重不同能力，不按批次单纯递增难度。

## Global Constraints

- 考试结构：50 道单选，每题 1 分；25 道多选，每题 2 分；满分 100 分，80 分及格，120 分钟。
- 考点权重依次为 17%、15%、20%、16%、16%、16%，保持现有组卷算法的整数配额。
- 单选题 4 个选项、1 个正确答案；多选题 4 个选项、2 或 3 个正确答案，沿用现有数据格式。
- 每题具备业务情境或工程问题、明确问法、答案、解析及可追溯知识依据。
- 不照搬官网截图原文；不使用“按课程”“教程指出”作为题干前提。
- 不凭更换公司名、业务名或数字生成实质重复题；相同考点的变式应改变约束、诊断线索或决策重点。
- 解析说明正确项成立的条件，并逐项说明干扰项的问题；避免“更先进”“效果更好”等无依据判断。
- 以大纲能力为主线，控制教程专属命令、路径、版本细节的比例；涉及具体产品能力时核对官方资料。
- 保持已发布题目 id 和数据字段兼容；新增题目从各文件现有最大编号继续追加。
- 本任务聚焦模拟题扩充；原有 300 道练习题、学习卡片、知识地图及面试题库不在扩充范围。
- 不把“450 道相当于六场题量”表述为“连续六场绝不重复”：现有组卷仅排除上一场题目。
- 本计划不包含推送、发布或自动提交；需要发布时再执行相应流程。

## Review Focus

1. **覆盖偏移：** 不能只覆盖官网 20 道样题的主题，需逐条对应 V4 核心知识点；Task 1 建立覆盖表，各批回填并核查。
2. **答案歧义：** “最合适”必须由题干条件支持，多选题不得把“可能有用”混同于“本题成立”；各批逐题核查。
3. **计算与指标边界：** 成本题写清输入输出单价、调用量、计费单位和取整口径；指标题写清判断条件，避免把趋势说成必然；各批独立复算和复核。
4. **数量写死：** 扩充后不能仍按 150 道严格校验；Task 3 更新分阶段目标及关联测试，不能通过放宽校验掩盖缺题。
5. **应用兼容：** 旧题 id、旧成绩和错题仍可查询，模考及离线加载可使用新题；Task 3–6 验证数据、组卷及实际手机视口流程。

### 各批重点

- **第一批：补缺与定风格。** 先审计 V4 覆盖，再优先补充未覆盖或仅由操作细节题覆盖的能力。重点检查 API 安全与计费、提示词边界、多轮检索、专家评测、训练基础与蒸馏路径、多模态架构及生产稳定性等是否已有充分题目；这些是审计方向，不是已确认的缺口。
- **第二批：拓宽业务场景。** 在六个模块中扩展技术选型、故障根因和约束条件变化，减少题干及干扰项套路重复。
- **第三批：加强综合判断。** 增加条件完整的成本计算、指标解读，以及 RAG / 微调 / 工具调用等跨模块方案选择；每题按主要考查能力归入一个模块。
- **第四批：补齐与平衡。** 根据覆盖表补缺，平衡难度、答案分布和场景多样性，检查全部新增题及与原题的重复、冲突和歧义。

以上为各批重点，不是排他范围；每批都应覆盖六个模块并形成可用题库增量。

## 四、每批共同验收

所有命令在 `acp-study-app/` 运行。

1. **内容核查：** 对照 V4、教程及必要的官方一手资料，逐题核对事实、适用条件、答案与解析；记录覆盖表。统计题型、场景、答案位置及实质重复情况。
2. **严格题库校验：** 运行 `npm run validate`，应输出该阶段的模拟题累计数量且无错误；不能以 `--allow-partial` 作为批次完成依据。
3. **单元回归：** 运行 `npm test`，数量及有效 fixture 应与当前阶段目标一致；组卷仍是 50 单选、25 多选，题量充足时与上一场无交集。
4. **手机流程回归：** 运行 `npm run e2e`，检查模考开始、答题交卷、成绩回看、新题错题复习、离线加载，以及现有手机视口下的长题干和长选项显示。
5. **兼容与更新：** 核查旧题和历史记录可查询，题量文案与实际一致，缓存版本包含本批更新；记录命令和实际结果后再勾选批次完成。

首次执行时先确认依赖和本机环境是否可用。检查失败需记录原因并修复或说明真实阻塞，不能宣称该批验收通过。

内容覆盖和题目歧义需要人工判断，结构测试通过不能代替逐题核查。
