## S01｜应用开发｜单选｜多轮对话费用（中等）

某客服使用无状态文本生成 API，每轮完整发送此前消息。系统提示为 1000 Token；首轮用户输入 200 Token、模型输出 300 Token；第二轮用户新增 100 Token、模型输出 200 Token。题中所有消息的合计 Token 数恰好等于各消息给定数量之和，不计额外协议开销。假设输入价格为 2 元／千 Token，输出为 6 元／千 Token，无缓存折扣及其他费用，两轮总费用是多少？

- A. 5.60 元。
- B. 8.60 元。
- C. 8.00 元。
- D. 17.20 元。

<details>
<summary>查看答案与解析</summary>

**答案：B。**

- 首轮输入为 1000＋200＝1200 Token；第二轮输入为 1000＋200＋300＋100＝1600 Token。首轮模型回复在第二轮作为历史输入再次计费。
- 输入合计 2800 Token，输出合计 500 Token，费用为 2800÷1000×2＋500÷1000×6＝8.60 元。
- A 漏算第二轮重复携带的系统提示和首轮消息；C 漏算作为历史输入的首轮模型回复；D 在正确合计之后又重复计费。

**V4 考点：** API 安全管理与 Token 计费；多轮对话。

**课程依据 / 拟入库 source：** `2_1_用大模型构建新人答疑机器人`（1.5 多轮对话、上下文成本）。

**补充核查：** [阿里云百炼多轮对话](https://help.aliyun.com/zh/model-studio/multi-round-conversation)说明历史消息会在后续请求中重复处理和计费。本题单价为假设值，不代表某个产品的现价。

</details>

## S02｜应用开发｜多选｜客户端密钥泄露（基础）

某手机网页把长期有效的模型 API Key 写入前端配置。发布后，团队发现用户能从浏览器网络请求中复制密钥。要阻止旧密钥继续被滥用，并避免再次暴露长期密钥，以下哪些措施合理？

- A. 删除已暴露的旧密钥，更新调用方凭据，并排查异常调用记录。
- B. 重新压缩前端脚本，用编码后的旧密钥替换明文，继续直接调用。
- C. 由鉴权后的业务后端调用模型，在服务端读取并保管新的长期密钥。
- D. 隐藏网页中的密钥配置入口，仅允许网页通过 HTTPS 发起模型请求。

<details>
<summary>查看答案与解析</summary>

**答案：A、C。**

- A：前端修改不能使攻击者已经复制的旧密钥失效，需要撤销旧密钥，并检查泄露期间的调用。
- C：将长期密钥留在服务端，手机网页访问经过鉴权的业务接口，才能避免继续向浏览器分发该密钥；后端还应执行调用权限与额度控制。
- B：压缩和编码可被还原，旧凭据也仍然有效。
- D：HTTPS 保护传输过程，不能阻止浏览器使用者查看自己发出的请求；隐藏入口也不能撤销凭据。

**V4 考点：** API 安全管理与 Token 计费。

**课程依据 / 拟入库 source：** `2_1_用大模型构建新人答疑机器人`（1.3 API Key 安全）。

**补充核查：** [获取与配置百炼 API Key](https://help.aliyun.com/zh/model-studio/get-api-key)明确提示长期密钥不应配置在客户端，主动删除后立即失效。本题采用后端代理方案，不考临时凭据的产品限制。

</details>

## S03｜提示词工程｜单选｜结构正确与金额正确（中等）

优惠核算助手已经能稳定输出合法 JSON，但偶尔把“满 200 元减 20 元”算错。促销规则完整且固定，结果将自动用于结算，业务要求金额必须通过确定性校验。以下哪种改进最合理？

- A. 将温度设为 0，并在提示词中重复“金额不得出错”，免去后续校验。
- B. 用 JSON Schema 限定金额字段为数值，通过结构校验就直接结算。
- C. 保留原有计算方式，把金额字段改为字符串，降低 JSON 解析失败率。
- D. 用规则与临界示例改善提示词，并在结算前用业务代码复核金额。

<details>
<summary>查看答案与解析</summary>

**答案：D。**

- D：提示词和边界示例能改善表现，确定性业务规则则应由代码校验；模型输出通过校验后才能进入自动结算。
- A：降低采样随机性不等于金额必然正确，重复要求也不能替代校验。
- B：字段类型正确不能证明满减门槛、计算过程和最终金额正确。
- C：改变字段类型只影响表示方式，不能修复计算逻辑。

**V4 考点：** 提示词的适用边界与局限；结构化输出与格式控制。

**课程依据 / 拟入库 source：** `2_3_优化提示词改善答疑机器人回答质量、4_3_大模型应用生产实践`（输出格式、示例、复杂计算，以及 2.1.5 不要默认依赖大模型）。

**与原题区别：** 原 `prompt-m001` 主要处理 JSON 格式不合法；本题在 JSON 已合法的前提下，区分格式校验与业务正确性校验。

</details>

## S04｜提示词工程｜多选｜Few-shot 边界示例冲突（中等）

工单助手要按规则分类：“当前时刻已比承诺发货时刻晚至少 48 小时，且仍未发货”才标为“超时”。提示词正文写明了这条规则，但示例把恰好晚 48 小时、且仍未发货的工单标为“未超时”，也没有发货状态的对照示例，导致边界工单分类不稳。以下哪些调整最有针对性？

- A. 增加更多远低于 48 小时的示例，保留现有边界示例，平衡类别数量。
- B. 修正恰好晚 48 小时且未发货的示例，使其标签与正文的规则一致。
- C. 将当前示例重复多次并放到提示词末尾，提高边界标签被模型关注的概率。
- D. 补充时长相同、发货状态不同的对照示例，体现两个条件必须同时成立。

<details>
<summary>查看答案与解析</summary>

**答案：B、D。**

- B：示例与规则冲突会让任务定义不一致，应先修正标签，而不是扩大矛盾数据。
- D：对照示例能展示“时间门槛＋未发货”的联合条件，减少只看时长的错误。
- A：远离边界的样本无法修复当前的错误边界标签，也未补充发货状态条件。
- C：重复错误示例会强化错误模式，位置调整不能解决定义冲突。

**V4 考点：** 系统提示词设计；Few-shot。

**课程依据 / 拟入库 source：** `2_3_优化提示词改善答疑机器人回答质量`（4.1 清晰表达需求、4.4 提供少样本示例）。

**与原题区别：** 原 `prompt-m019` 着重样本质量和输出格式；本题要求识别数值边界与联合条件，确认后应避免剩余题目继续复用相同的“修正示例”结论。

</details>

## S05｜RAG｜单选｜追问进入生成阶段却未进入检索（中等）

员工先问“外地出差住宿上限是多少”，再追问“如果去深圳呢”。完整对话历史已传给回答模型，但检索日志显示第二轮只用“如果去深圳呢”查询，召回的是深圳办公地点。知识库有深圳差旅标准，直接用完整问题检索也能命中。应优先改进哪个环节？

- A. 检索前结合历史，把追问改写为“去深圳出差的住宿上限是多少”。
- B. 生成时再次补入历史，继续使用“如果去深圳呢”作为检索查询。
- C. 保持检索查询不变，扩大回答模型上下文窗口以容纳更多对话。
- D. 保留当前查询，换用重排序模型对深圳办公地点片段重新评分。

<details>
<summary>查看答案与解析</summary>

**答案：A。**

- A：根因在检索查询缺少“出差住宿上限”这一语义主体；应先结合相关历史消解指代，再检索。
- B：生成模型已经看到历史，再次补入不能直接纠正上游的查询内容。
- C：当前缺失的是检索阶段的语义，不是回答模型的窗口容量。
- D：重排不能凭空补回候选集中没有的差旅依据，优先修复查询才符合题干证据。

**V4 考点：** 多轮对话场景下的检索适配。

**课程依据 / 拟入库 source：** `2_1_用大模型构建新人答疑机器人、2_5_优化RAG应用提升问答准确度`（多轮历史、检索前问题改写）。

**补充核查：** [LlamaIndex Condense Question](https://developers.llamaindex.ai/python/examples/chat_engine/chat_engine_condense_question/)说明先结合会话历史形成独立问题，再查询。课程 2.5 未直接讲解这一完整多轮改写流程，因此此处明确列出补充依据。

</details>

## S06｜RAG｜多选｜专家标准与自动评测不一致（中等）

报销问答的自动评测得分很高，业务专家却发现回答漏掉“首次报销需提交审批单”。排查确认：参考文档包含该条件，但评测参考答案也漏写了它，裁判评分规则未检查该项。以下哪些处理合理？

- A. 由业务专家修订参考答案与关键检查项，并注明适用制度版本。
- B. 保留现有评测标准，仅扩大检索 Top K，直到自动得分进一步提高。
- C. 用专家标注样本校准裁判，并在未参与校准的样本上检验漏判情况。
- D. 将裁判换成更大模型，继续使用原参考答案和原评分规则验收。

<details>
<summary>查看答案与解析</summary>

**答案：A、C。**

- A：评测的参考目标本身缺少业务关键条件，应先由专家修正，否则高分可能对应错误目标。
- C：自动裁判需要与专家标准对齐，并用独立样本检查能否发现同类遗漏。
- B：文档已有条件，调整检索也无法纠正参考答案和评分规则中的缺项。
- D：模型能力提升不能保证其主动纠正错误参考标准，不能作为保持错误基准的理由。

**V4 考点：** 专家引导评测体系建设。

**课程依据 / 拟入库 source：** `2_4_自动化评测答疑机器人的表现、2_3_优化提示词改善答疑机器人回答质量`（2.4 的 5.1、5.4，2.3 的 4.7）。

**与原题区别：** 原 `rag-m014` 要求先建立评测基线；本题已有基线，诊断的是评测目标遗漏业务条件。

</details>

## S07｜微调｜单选｜学习率与训练震荡（中等）

团队对相同数据和同一基座做 LoRA 微调。学习率为 0.0001 时，训练与验证损失均平稳下降；其他设置不变，将学习率改为 0.1 后，两种损失都剧烈震荡。数据格式、标签及梯度计算已检查正常，恢复原学习率后震荡消失。以下哪种解释最合理？

- A. 出现典型过拟合，应继续训练，使验证损失最终接近训练损失。
- B. LoRA 可训练参数过少，调高采样温度能减轻训练损失的震荡。
- C. 参数更新步长过大，恢复较小学习率后再评估收敛和任务指标。
- D. 验证集规模不足，应将验证样本加入训练，消除两条曲线差异。

<details>
<summary>查看答案与解析</summary>

**答案：C。**

- C：学习率控制参数更新幅度。题干提供了只改变学习率、恢复后现象消失的对照证据，支持步长过大导致训练不稳定的判断。
- A：典型过拟合是训练表现持续改善、验证表现恶化；本题两种损失同步震荡，且与学习率变化相关。
- B：采样温度主要控制推理输出的随机性，不能修复训练优化器的更新步长。
- D：混入验证样本会损害独立评估，且不能解释学习率恢复后的对照结果。

**V4 考点：** 梯度下降、损失函数；LoRA 微调与训练调参。

**课程依据 / 拟入库 source：** `4_1_用蒸馏让小模型掌握专业能力`（5.1 梯度下降与学习率、5.3 训练状态判断）。

**补充核查：** [PyTorch 参数优化教程](https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html)说明学习率影响更新步长和收敛行为。本题不要求推导梯度公式。

</details>

## S08｜微调｜多选｜合成数据泄露到验证集（中等偏难）

工单训练集由教师模型扩写生成，每条原始工单产生多个近似改写。团队随机按行拆分训练集和验证集，验证准确率 99%，真实新工单却明显较差。抽查发现同一原始工单的改写分布在两边。为更可信地评估泛化能力，以下哪些做法合理？

- A. 按原始工单分组拆分，避免其近似改写跨越训练与验证集合。
- B. 另留真实业务验收集，不参与样本生成、训练和参数选择。
- C. 把错误的新工单立即加入训练，再用同一批工单报告独立验收成绩。
- D. 对拆分后的样本做跨集合近重复检查，并检查类别与边界场景覆盖。

<details>
<summary>查看答案与解析</summary>

**答案：A、B、D。**

- A：按独立原始工单分组比按改写行随机拆分更能防止相似内容泄露。
- B：保留未参与开发决策的真实验收集，才能进一步检验对新分布的表现；不能反复用它选择参数。
- D：分组后仍可能有不同工单文本近重复，需核查；也不能因去重而漏掉重要业务类别。
- C：加入训练后，这批工单就不再是独立验收样本，可以用于后续改进，但需要新的独立集合评估。

**V4 考点：** 训练数据合成；过拟合与效果评估。

**课程依据 / 拟入库 source：** `4_1_用蒸馏让小模型掌握专业能力`（数据合成、训练状态判断、效果评测）。

**补充核查：** [scikit-learn 数据泄露说明](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)支持独立评估数据不能参与训练和开发决策的原则。“按原始工单分组”是针对题中近重复生成方式的工程应用，不冒充课程原文。

</details>

## S09｜智能体｜单选｜固定流程与自主规划（基础）

企业报销流程规定必须依次经过“提取票据信息→核验发票→按规则计算→人工审批→付款”。所有分支与异常处理均已有明确规则，不允许临时跳过或增加付款步骤。团队希望接入模型提取信息，以下架构最合适？

- A. 让自主 Agent 每次重新规划完整流程，按其判断选择审批和付款顺序。
- B. 用固定工作流控制步骤与状态，模型负责信息提取，异常走既定分支。
- C. 把流程完整写进系统提示词，让模型自主调用付款工具并自查步骤。
- D. 用多个 Agent 投票决定当次审批路径，得票最高的路径直接执行。

<details>
<summary>查看答案与解析</summary>

**答案：B。**

- B：流程、分支和权限边界已确定，适合由工作流强制编排；信息提取等局部节点仍可调用模型。
- A：无需每次重新探索步骤，且不能让模型改变强制审批顺序。
- C：提示词和自查不能替代程序中的状态流转与授权约束。
- D：投票不能改变业务规定，增加 Agent 也不能自动带来流程合规性。

**V4 考点：** 固定流程 vs 自主规划。

**课程依据 / 拟入库 source：** `3_2_让Agent学会规划与执行`（工作流、从固定流程到自主规划）。

**与原题区别：** 原 `agent-mm-m003` 需要在执行失败后重排计划；本题明确所有路径已知，考查选择固定流程的条件。

</details>

## S10｜智能体｜多选｜语音会议处理流程（中等）

会议助手需要“录音→可存档文字→文字摘要→摘要语音播报”。现有语音识别、文本摘要和语音合成服务均已满足单项质量要求；录音转写费用较高，业务要求每一步结果可追溯。以下哪些设计合理？

- A. 用图像理解服务处理录音二进制，直接得到摘要，省去单独转写阶段。
- B. 按语音识别、文本摘要、语音合成串联，记录会议标识和各阶段产物。
- C. 语音播报生成失败时，复用已确认的文字摘要，仅重试语音合成阶段。
- D. 只保存最终语音文件，任何阶段失败都重新转写全部录音再生成摘要。

<details>
<summary>查看答案与解析</summary>

**答案：B、C。**

- B：语音识别负责录音转文字，文本模型负责摘要，语音合成负责播报；中间产物支持追溯和复用。
- C：下游失败不代表上游结果失效，复用已确认摘要可避免重复转写和重复费用。
- A：图像理解并不等同于音频识别，题干也未提供可从音频直接完成任务的视觉服务能力。

## S11｜生产实践｜单选｜离线指标与业务价值（中等）

客服摘要模型离线准确率达到 95%，试点后人工处理每单的总时长却没有下降。访谈发现，员工仍需把摘要逐项复制到旧系统，遇到遗漏还要回读原对话。负责人准备扩大上线，以下哪项工作应优先开展？

## S12｜生产实践｜多选｜有副作用操作的超时重试（中等偏难）

客服 Agent 调用退款工具后超时，订单系统可能已完成退款，但响应丢失。工具支持按退款请求号查询结果，也支持相同请求号幂等提交。系统要恢复服务并避免重复退款，以下哪些处理合理？

- A. 每次超时生成新退款请求号并立即重试，直到收到成功响应。
- B. 按原请求号查询业务状态，确认结果后更新工单和用户提示。
- C. 确需重试时复用原请求号，并由退款服务保证幂等处理。
- D. 限制查询与重试次数，结果持续不明时转人工核对并保留记录。

<details>
<summary>查看答案与解析</summary>

**答案：B、C、D。**

- B：超时表示结果未知，不能直接推断操作失败；查询已有请求有助于恢复真实状态。
- C：同一业务请求复用原请求号，配合服务端幂等实现，才能避免重试造成额外退款。
- D：有界重试及人工兜底控制持续不确定状态，审计记录用于后续核对。
- A：新请求号可能被视为新退款，立即反复提交会产生重复副作用。

**V4 考点：** 生产稳定性保障；工具执行的可靠性。

**课程依据 / 拟入库 source：** `4_3_大模型应用生产实践、3_1_Agent基础与工具调用`（容灾与错误处理、工具执行边界）。

**补充核查：** [Amazon Builders’ Library：安全重试与幂等 API](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/)说明超时后的副作用不确定性及调用方请求标识。此题应用通用分布式系统原则，不考 AWS 产品使用。

**与原题区别：** 原 `production-m019` 主要应对模型 API 限流和超时；本题是可能已成功执行的退款写操作，不能直接套用无副作用请求的重试策略。
